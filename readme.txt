Federated, privacy-safe search and discovery infrastructure for the Sabri Social Homeopathy Platform.

== Description ==

File 26 is the canonical owner of derivative indexing, federated retrieval, query understanding, organic ranking policies, consent-first recommendations, controlled taxonomy/classification, owner-sourced knowledge-graph projections, global verified-doctor ranking orchestration and ranking appeals.

File 26 does not own canonical posts, doctors, clinics, lessons, books, video, reels, PDFs, research, marketplace listings, the global application shell or File 25 result-card visuals. Canonical owner modules register versioned connectors and retain all write authority.

Version 1.1.0 corrects the three-plan audit findings by adding:

* runtime-enforced versioned ranking policies and dual-approved rollback to the previous policy;
* active production-lane isolation for connector retrieval;
* exact phrase, bounded spelling tolerance and Urdu/Roman-Urdu transliteration handling;
* chunked corpus scanning with truthful partial-result disclosure;
* approved classification IDs and bounded public knowledge-graph relationship signals;
* complete public filters, facets and sorting;
* explicit recommendation consent, interests, hide/not-interested, undo, reset and opt-out controls;
* request-bound guest/session discovery without hidden guest profiling;
* dedicated operator, curator, ranking-approver and auditor roles;
* versioned, explainable global and contextual verified-doctor ranking views;
* evidence-bound doctor-ranking appeals with independent review and privacy export/erasure support;
* strict required owner-contract and external staging/rollback activation gates.

== Installation ==

1. Upload the deterministic ZIP in WordPress Plugins > Add New > Upload Plugin.
2. Activate the plugin.
3. Assign distinct institutional File 26 roles/capabilities to separate authorized users.
4. Register canonical owner adapters through the versioned owner-connector contract.
5. Complete connector lifecycle stages: proposed, contract tested, shadow, approved and active.
6. Complete File 00, File 20, File 24 and File 25 integration evidence.
7. Complete migration, backup/restore and rollback rehearsals in Hostinger-equivalent staging.
8. Use Search > File 26 > Activation only after all required owner contracts and external evidence pass.

Activation is intentionally fail closed. Installing or activating the WordPress plugin does not automatically enable public search or personalization.

== Privacy ==

Raw query text sampling is disabled by default. Search telemetry uses coarse, daily rotating aggregate buckets. Personalized recommendations require explicit consent. Guest/session discovery is request-bound and is not stored as a hidden profile. Users can export or erase recommendation controls, feedback and ranking-appeal data through WordPress privacy tools; minimal pseudonymized appeal records may be retained for fairness/audit integrity.

== Frequently Asked Questions ==

= Does File 26 copy or replace canonical content databases? =

No. It stores rebuildable derivative search documents and owner references only.

= Can shadow connector data appear in public search? =

No. Shadow and approved lanes may be used for governed validation/indexing, but only an active production connector can serve public or member retrieval.

= Does donation, payment, advertising, followers or Founder preference improve ranking? =

No. Those signals are prohibited from organic and verified-doctor ranking.

= Are doctor rankings appealable? =

Yes. An affected verified doctor or authorized representative can submit an evidence-bound appeal. A conflicted appellant cannot review the same appeal.

= Is version 1.1.0 production complete? =

No. It is a coded, packaged and automated-QA candidate only after green CI. Hostinger staging acceptance, real owner connectors, real-role workflows, backup/restore, rollback, Founder approval, live deployment and operational evidence remain separate gates.
