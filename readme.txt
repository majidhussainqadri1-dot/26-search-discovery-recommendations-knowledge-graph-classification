Federated, privacy-safe search and discovery infrastructure for the Sabri Social Homeopathy Platform.

== Description ==

File 26 is the canonical owner of derivative indexing, federated retrieval, query understanding, organic ranking policies, consent-first recommendations, controlled taxonomy/classification, owner-sourced knowledge-graph projections, global verified-doctor ranking orchestration, ranking appeals and the Future Search & Knowledge Intelligence Superset 24.

File 26 does not own canonical posts, doctors, clinics, lessons, books, video, reels, PDFs, research, marketplace listings, private user data, clinical truth, notification delivery, external evidence truth, the global application shell or File 25 result-card visuals. Canonical owner modules register versioned connectors/providers and retain all write and authorization authority.

Version 1.3.0 preserves the complete v1.2.0 baseline and adds F26-FUT-01 through F26-FUT-24:

* grounded conversational discovery with returned-source citations and non-prescriptive safety attestation;
* intelligent query planning with bounded subqueries and optional federated execution;
* Urdu/Roman-Urdu/Arabic-script expansion plus approved cross-language semantic variants;
* optional second-stage semantic reranking over only the already eligible candidate set;
* owner-reference multimodal and Urdu/English voice search without File 26 media/audio retention;
* page, paragraph, chapter, lesson and timestamp search only from owner-proven segments;
* find-similar/query-by-example from an eligible canonical seed;
* scholar/research mode with evidence/edition/source/date filters and optional reproducibility snapshots;
* deterministic result clustering;
* bounded provenance-rich Graph Explorer and evidence/contradiction maps;
* entity/name/edition disambiguation without automatic merge;
* historical/as-of search that requires an actual owner snapshot and never substitutes current results;
* account-owned research trails storing canonical references only;
* saved-search alert registry with File 19 as notification-delivery owner;
* local-first browser search history, no automatic network sync, explicit opt-in server sync and sensitive-query blocking;
* recommendation transparency, effective less-personalization control and anti-filter-bubble breadth modes;
* doctor/clinic geo discovery with File 07/File 08 availability truth and click/action-time owner revalidation;
* user search modes and bounded smart commands;
* step-up isolated Private Search Vault that never uses the public File 26 index;
* approved, separately labelled external evidence connectors that never silently merge into organic ranking;
* read-only Search Intelligence & Relevance Laboratory with no direct production policy mutation.

Provider-dependent Future features fail closed or return an explicit unavailable state. File 26 never fabricates canonical, historical, clinical, page/timestamp, availability or external evidence.

Version 1.2.0 implemented the later three-central-plan / continuous-value File 26 requirements, including advanced search, saved queries, public ranking constitution, zero-result recovery, search-safety diversion, aggregate editorial radar, truthful freshness evidence, single-free-tier ranking parity and hard prohibition on donation/payment/paid promotion/follower/Founder favoritism signals.

The current File 26 implementation remains derivative: symptom/remedy canonical knowledge stays with its native knowledge/Radar owners, and trend truth remains with File 15. File 26 may search, rank or project owner-supplied contracts but does not duplicate source of truth.

== Installation ==

1. Upload the deterministic ZIP in WordPress Plugins > Add New > Upload Plugin.
2. Activate the plugin.
3. Assign distinct institutional File 26 roles/capabilities to separate authorized users.
4. Register canonical owner adapters through the versioned owner-connector/provider contracts.
5. Complete connector lifecycle stages: proposed, contract tested, shadow, approved and active.
6. Complete File 00, File 20, File 24 and File 25 integration evidence.
7. Complete migration, backup/restore and rollback rehearsals in Hostinger-equivalent staging.
8. Verify Future provider boundaries: File 19 notification delivery, File 07/08 availability truth, private-vault authorization and approved external evidence connectors.
9. Use Search > File 26 > Activation only after all required owner contracts and external evidence pass.

Activation is intentionally fail closed. Installing or activating the WordPress plugin does not automatically enable public search, personalization or provider-dependent Future features.

== Privacy ==

Raw query text sampling is disabled by default. Search telemetry uses coarse aggregate buckets. Personalized recommendations require explicit consent. Guest/session discovery is request-bound and is not stored as a hidden profile. Saved queries are account-owned, never used as a hidden personalization signal, and are exportable/erasable. Sensitive saved queries require explicit confirmation and approved encrypted storage. Editorial content-gap text is retained only after explicit non-sensitive submission and without user identity.

Future search history is browser/device-local by default. Merely loading the Future script does not transmit history. Server history sync requires an explicit opt-in action, blocks queries classified as sensitive, is bounded/de-duplicated and can be exported/erased. Research trails, saved-search alerts, opt-in server history and discovery controls are included in WordPress privacy export/erasure. Private Search Vault responses are no-store and use native-owner authorization; File 26 public index is never used for the vault.

== Frequently Asked Questions ==

= Does File 26 copy or replace canonical content databases? =

No. It stores rebuildable derivative search documents and owner references only.

= Can shadow connector data appear in public search? =

No. Shadow and approved lanes may be used for governed validation/indexing, but only an active production connector can serve public or member retrieval.

= Does donation, payment, advertising, followers or Founder preference improve ranking? =

No. Those signals are prohibited from organic and verified-doctor ranking and remain prohibited in Future reranking/laboratory contracts.

= Does conversational or multimodal search diagnose patients? =

No. File 26 may discover educational owner-sourced content. Autonomous diagnosis, prescription, dose/potency generation and patient-image diagnosis are outside this search module.

= Are external web/evidence results mixed into platform ranking? =

No. Only specifically approved external evidence connectors may return results, and those results remain a separately labelled lane with provenance/rights information. They are not canonical platform truth and are not silently merged into organic ranking.

= Is private search part of the public search index? =

No. Private Search Vault is a separate step-up, native-owner-authorized adapter path and explicitly reports `public_index_used=false`.

= Are doctor rankings appealable? =

Yes. An affected verified doctor or authorized representative can submit an evidence-bound appeal. A conflicted appellant cannot review the same appeal.

= Is version 1.3.0 production complete? =

No. Repository coding, deterministic packaging and automated QA are evidence statuses separate from Hostinger staging, deployed database/migration state, live deployment and operations. Staging acceptance, real owner/provider connectors, real-role workflows, browser/accessibility evidence, backup/restore, rollback, Founder release approval, live re-test and operational SLO evidence remain separate gates.
