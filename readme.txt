Federated, privacy-safe search and discovery infrastructure for the Sabri Social Homeopathy Platform.

== Description ==

File 26 is the canonical owner of derivative indexing, federated retrieval, query understanding, organic ranking policies, consent-first recommendations, controlled taxonomy/classification, owner-sourced knowledge-graph projections, global verified-doctor ranking orchestration and ranking appeals.

File 26 does not own canonical posts, doctors, clinics, lessons, books, video, reels, PDFs, research, marketplace listings, the global application shell or File 25 result-card visuals. Canonical owner modules register versioned connectors and retain all write authority.

Version 1.2.0 preserves the complete 1.1.0 corrective baseline and implements the later three-central-plan / continuous-value File 26 requirements, including:

* federated search and honest facets over canonical owner connectors;
* exact phrase, bounded spelling tolerance and Urdu/Roman-Urdu/Arabic-script query handling;
* advanced search by author/source/date/fields/excludes plus explicit account-owned saved queries;
* public versioned ranking constitution and non-vague “why this result” contract;
* global verified-doctor Top 10/100/1000/All Verified ranking, contextual views, monthly recompute and appeals;
* zero-result recovery without fabricated results, with explicit non-sensitive content-gap submission;
* search-safety classification and emergency/clinical diversion without fabricated local emergency details;
* privacy-minimized editorial radar using aggregate metrics and explicitly submitted non-sensitive content gaps;
* index-freshness evidence that reports unknown when source update timing is unavailable instead of inventing freshness;
* single-free-tier ranking parity and hard prohibition on donation/payment/paid promotion/follower/Founder favoritism signals;
* Sabri Green #087A4E only as a File 25 visual-token fallback; File 20 remains shell owner and File 25 remains visual owner;
* pinned GitHub Actions dependencies and expanded central-plan regression gates.

The current File 26 implementation remains derivative: symptom/remedy canonical knowledge stays with its native knowledge/Radar owners, and trend truth remains with File 15. File 26 may search, rank or project those owner-supplied contracts but does not duplicate their source of truth.

== Installation ==

1. Upload the deterministic ZIP in WordPress Plugins > Add New > Upload Plugin.
2. Activate the plugin.
3. Assign distinct institutional File 26 roles/capabilities to separate authorized users.
4. Register canonical owner adapters through the versioned owner-connector contract.
5. Complete connector lifecycle stages: proposed, contract tested, shadow, approved and active.
6. Complete File 00, File 20, File 24 and File 25 integration evidence.
7. Complete migration, backup/restore and rollback rehearsals in Hostinger-equivalent staging.
8. Use Search > File 26 > Activation only after all required owner contracts and external evidence pass.

Activation is intentionally fail closed. Installing or activating the WordPress plugin does not automatically enable public search or personalization.

== Privacy ==

Raw query text sampling is disabled by default. Search telemetry uses coarse aggregate buckets. Personalized recommendations require explicit consent. Guest/session discovery is request-bound and is not stored as a hidden profile. Saved queries are account-owned, never used as a hidden personalization signal, and are exportable/erasable. Sensitive saved queries require explicit confirmation and use shorter retention. Editorial content-gap text is retained only after explicit submission, only when the query is non-sensitive, and without user identity. Users can export or erase recommendation controls, feedback, ranking-appeal data and saved-query data through WordPress privacy tools.

== Frequently Asked Questions ==

= Does File 26 copy or replace canonical content databases? =

No. It stores rebuildable derivative search documents and owner references only.

= Can shadow connector data appear in public search? =

No. Shadow and approved lanes may be used for governed validation/indexing, but only an active production connector can serve public or member retrieval.

= Does donation, payment, advertising, followers or Founder preference improve ranking? =

No. Those signals are prohibited from organic and verified-doctor ranking.

= Are doctor rankings appealable? =

Yes. An affected verified doctor or authorized representative can submit an evidence-bound appeal. A conflicted appellant cannot review the same appeal.

= Is version 1.2.0 production complete? =

No. Repository coding, deterministic packaging and automated QA are evidence statuses separate from Hostinger staging, deployed database/migration state, live deployment and operations. Staging acceptance, real owner connectors, real-role workflows, browser/accessibility evidence, backup/restore, rollback, Founder release approval, live re-test and operational SLO evidence remain separate gates.
